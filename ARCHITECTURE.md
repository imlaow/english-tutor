# English Learning App Architecture & Development Guidelines

## 1. Core Tech Stack
- **UI Framework**: Kotlin + Jetpack Compose. Material Design is the default, but the app now carries a design system of its own — see `DESIGN.md`, which supersedes this line wherever the two disagree. Reuse the components in `ui/DesignSystem.kt` rather than inventing new ones.
- **Architecture Pattern**: MVVM (Model-View-ViewModel) with Unidirectional Data Flow (UDF).
- **Dependency Injection**: Manual Dependency Injection (Manual DI) - Use ViewModelProvider.Factory. Do not introduce third-party frameworks like Hilt/Koin.
- **Local Database**: Room.
- **Cloud Database**: Neon PostgreSQL (Interact via Retrofit/Ktor. API Keys injected via local.properties).
- **AI Chat**: Google Gemini API.
- **TTS Service**: Azure Cognitive Services Speech SDK (en-US-JennyNeural).

## 2. Module Responsibilities & Package Structure
All code must strictly follow the structure below. Cross-layer direct calls are strictly prohibited:
- `ui/`: Contains only Compose pure functions and UI state classes. No network, database, or complex business logic allowed.
- `viewmodel/`: Manages UI State and handles user Intents. Can only call Repositories. Direct calls to DAOs or external APIs are forbidden.
- `data/`: 
  - `local/`: Room Database, DAOs, Entities.
  - `remote/`: Network APIs (Neon, Gemini), DTO data models.
  - `repository/`: Repository implementations, responsible for coordinating data sources.
- `manager/`: Encapsulates independent services, e.g., `TtsManager`.

## 3. Core Data Flow - Strictly Enforced!
1. **User Profile Data**:
   - After the JSON is generated by Gemini, it **MUST** be serialized by the Repository and saved into the local **Room database**.
   - When fetching recommended topics on the Home screen, the app must query the User Profile from the local Room database first before generating the prompt for Gemini.
2. **TTS Playback Logic**:
   - Playback control (play/pause/stop) must be handled via the `TtsManager` singleton. Instantiating the SDK directly within Compose UI is strictly prohibited.

## 4. Hard Rules for AI Agent (DO NOT IGNORE)
1. **Strict Single-Step Execution**: Each session is only allowed to execute ONE specific Task assigned by the user. Automatically planning and executing subsequent unassigned tasks is **STRICTLY PROHIBITED**!
2. **Design First, Implement Later**: Interface designs and data models must be confirmed by the user before writing concrete class implementations.
3. **Secure Configuration**: All API Keys must be read from `local.properties` into `BuildConfig`. Hardcoding plain text keys in the source code is strictly prohibited.
